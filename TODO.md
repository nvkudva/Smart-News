- [ ] P4, revisit later: keep the working store in R2 rather than the Actions cache. The cache works and costs nothing to run, but it has two limits. It can only be written from inside a workflow run — there is no public write API — so a store summarised on a laptop (with a local model, at no neuron cost) cannot be handed to the runner directly; it has to go through D1 and be hydrated back. And every run saves a new ~15MB entry against a 10GB per-repo allowance, so the cache fills in about a week and GitHub evicts least-recently-used; restore-keys always takes the newest, so hits stay reliable, but a bad eviction costs one full 16k-row hydrate. R2 fixes both: wrangler can put the object from anywhere, and storage is the account's own. Not urgent — a full hydrate is 0.3% of the daily read limit, so the thing being avoided is cheap
