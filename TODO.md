Split per component and co-locate (StoryCard.css beside StoryCard.tsx, imported by it - class names unchanged, no CSS Modules), use native nesting so each component's media queries live inside its own rules, keep the 117 :root/[data-theme] token blocks and the layout primitives (.shell, .feed, .pagehead) as styles/theme.css and styles/base.css, and declare @layer theme, base, components, utilities so ordering stops depending on file position. Separately: 28% of the file (21.5KB) is Tailwind that is never compiled - web/ has no PostCSS config and no Tailwind plugin, so @import "tailwindcss" inlines the package source and @theme and @tailwind utilities ship as at-rules the browser ignores; only its @layer base preflight does anything, so replace the import with an explicit reset we own. Do it as its own change with a visual check - the cascade-ordering risk is real
- [ ] Revisit whether web/src/components should be subfoldered. 27 files flat, and four kinds mixed: presentational (Logo, icons, StoryCard, CoverageSplit, StoryFraming, ExplorationDot, ExploreTiles, TabBar), interaction (StripScroller, CategoryPager, CategoryStrip, SubcategoryStrip, ReelKeys, SaveButton), settings controls (Theme, Mode, NavPlacement, PrefChips, CountryPicker, PlacePicker, GeoConsent, prefsChanged) and app infrastructure (AppHeader, HeaderAside, ServiceWorker, UpdateBanner, StoryWarm). - [ ] Make the app work offline from the cached data. Two separate things and only the second is a defect. First, the service worker is deliberately inert under vite dev (ServiceWorker.tsx returns early on import.meta.env.DEV and clears its caches), so going offline against localhost:5173 can never work - test offline against vite preview or the deploy, not the dev server. Second, the real bug: offline, sessionStamp() catches the failed /api/stamp and resolves to null by design, and readFresh in lib/load.ts then reads `stored && stamp && stored.stamp === stamp`, so a null stamp discards a perfectly good stored copy and load() falls through to a fetch that cannot succeed - the route throws and FeedError renders instead of the feed the browser is holding. A null stamp means "cannot verify", not "invalid": offline it should serve what is stored and say nothing, which is the whole point of keying on the stamp rather than a TTL. Check the same path in world.ts's resolve (its ?since delta branch has the same assumption), decide what /saved and /profile do offline given they are deliberately unpersisted, and add an offline case to web/tests - Playwright can drop the context offline, so this is testable rather than a claim
