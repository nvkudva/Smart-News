- [ ] Make the app work offline from the cached data. Two separate things and only the second is a defect. First, the service worker is deliberately inert under vite dev (ServiceWorker.tsx returns early on import.meta.env.DEV and clears its caches), so going offline against localhost:5173 can never work - test offline against vite preview or the deploy, not the dev server. Second, the real bug: offline, sessionStamp() catches the failed /api/stamp and resolves to null by design, and readFresh in lib/load.ts then reads `stored && stamp && stored.stamp === stamp`, so a null stamp discards a perfectly good stored copy and load() falls through to a fetch that cannot succeed - the route throws and FeedError renders instead of the feed the browser is holding. A null stamp means "cannot verify", not "invalid": offline it should serve what is stored and say nothing, which is the whole point of keying on the stamp rather than a TTL. Check the same path in world.ts's resolve (its ?since delta branch has the same assumption), decide what /saved and /profile do offline given they are deliberately unpersisted, and add an offline case to web/tests - Playwright can drop the context offline, so this is testable rather than a claim
